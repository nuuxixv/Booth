# 사양 시트 — A12 준비노트 템플릿 (Prep Note Templates)

> 이 시트는 **준비노트 템플릿 기능**(전용 테이블 · 여러 개 · 관리 UI · L2 적용 흐름)의 정보·기능·데이터 구조의 단일 진실 소스다.
> 시안과 실서비스 구현은 이 시트의 모든 항목을 1:1로 반영해야 한다.
> 임의 단순화·통합·생략은 건우님의 명시적 승인 후 이 시트를 먼저 갱신한 다음에만 허용된다.
> 신설 2026-10-12 (학회 개선 트랙 2차 — DB 변경 포함분). 건우님 2026-10-12 "권장안대로" 일괄 승인 범위.

## 설계 목표

> **"같은 학회의 준비노트를 매번 처음부터 쓰지 않는다. 검증된 뼈대를 꺼내 채우기만 한다."**

- 2026-06 백업 노트 5건 분석에서 **공통 뼈대**(차량 2대·단말기·공통 물품 체크리스트·사후 업무)가 반복됨을 확인했다. 매 학회 이 뼈대를 손으로 다시 쓰는 것이 출발점 Pain.
- 연 8일·연 800건 규모의 **드물게 하는 작업**이라 손에 안 익는다. 타팀 이관 대비 "뼈대를 꺼내 채우기만" 하는 경로가 핵심(`01_DESIGN_PRINCIPLES` 원칙 2 "한 번 보고 알아야 한다" / `project_handover_maintainability`).
- 템플릿은 **씨앗(seed)일 뿐**이다. 적용 = 준비노트에 본문을 복사해 넣는 것이고, 그 뒤로는 일반 준비노트 편집과 완전히 동일하다. 템플릿을 고치거나 지워도 **이미 적용된 노트에는 영향이 없다.**

## 범위 결정 (건우님 2026-10-12 확정)

|---|---|
| 저장 방식 | **전용 테이블 `prep_note_templates`** (prep_note 컬럼 재사용 아님). 여러 개 보유 가능 |
| 관리 진입 | 학회 목록(A10 L1) 상단 **"학회 목록 관리" 옆 버튼**("준비노트 템플릿"). `events:edit`만 |

## 사용자 시나리오

인싸이트/와박팀 직원(`events:edit`)이 새 학회 상세(L2)의 준비 노트를 처음 열면 비어 있다. "템플릿으로 시작"을 누르면 등록된 템플릿 중 하나를 고르고, 검증된 뼈대(차량·단말기·공통 물품 체크리스트·사후 업무)가 에디터에 채워진다. 이 학회에만 해당하는 검사 품목과 메모를 더 적고 저장한다. 뼈대 자체를 바꾸고 싶으면 학회 목록 상단 "준비노트 템플릿"에서 템플릿을 직접 수정한다. 뼈대 수정은 **다음에 적용할 노트부터** 반영되고 이미 쓴 노트는 건드리지 않는다.

## 1. 템플릿 관리 UI

### 1-1. 진입 (A10 반영 요청)
- [ ] A10 L1 PageHeader 우상단 액션에 **`준비노트 템플릿`(outlined)** 버튼 추가 — 기존 `학회 목록 관리`(outlined) 옆, `학회 추가`(contained) 왼쪽. Primary 채움 버튼은 `학회 추가` 1개 유지(`A10 §12-1`).
- [ ] 노출 권한 = `events:edit`. `events:view`만 있는 사용자에겐 **버튼 미노출**(관리 불가).
- [ ] 클릭 → `PrepNoteTemplateDialog` 오픈.

### 1-2. 형태 — 모달 1개, "목록 ↔ 편집" 모드 스왑 (권장안)
- [ ] **단일 `Dialog`(maxWidth="md", 모바일 fullScreen).** 내부가 "목록 뷰 ↔ 편집 뷰"로 모드 스왑한다.
- [ ] **권장 근거:**
  1. **L2 개요의 "읽기 요약 ↔ 편집 폼 모드 스왑" idiom(2026-07-28 채택, `L2 §5-2`)과 동일** — 팀이 이미 쓰는 패턴이라 학습 비용 0, 이관 친화.
  2. **모달 중첩 회피** — 목록 모달 + 편집 모달 2단보다 한 표면에서 전환하는 쪽이 비개발 운영자에게 혼란이 적다(`project_handover_maintainability`).
  3. Toast UI 에디터는 세로 공간(기본 420px)이 필요해 `SocietyManagementDialog`의 `maxWidth="sm"`로는 좁다 → `md` 폭을 에디터가 전부 쓴다.
- [ ] **기각한 대안:** (a) 전용 페이지 `/admin/events/templates` — 라우트·내비게이션 추가 비용이 "드물게 쓰는 도구"에 비해 과함. (b) 리스트 모달 + 편집 모달 2단 — 중첩 백드롭이 톤을 흐림. 둘 다 동작은 하나 위 근거로 모드 스왑 채택.

### 1-3. 목록 뷰
- [ ] `DialogTitle` = "준비노트 템플릿". 상단 보조 문구 1줄: "여기서 만든 템플릿을 학회 준비 노트에서 꺼내 쓸 수 있어요. 템플릿을 고쳐도 이미 작성한 노트에는 영향이 없습니다."
- [ ] 상단 우측 **"새 템플릿"** 버튼(contained, `events:edit`) → 편집 뷰(신규) 진입.
- [ ] 목록 행(List) — 각 행:
  - [ ] **이름**(`name`, primary, fontWeight 600)
  - [ ] **수정일**(`updated_at`, secondary caption, `YYYY.MM.DD` 점 표기·tnum)
  - [ ] 행 우측 액션 2: **수정**(편집 뷰 진입) · **삭제**(확인 다이얼로그)
- [ ] 정렬 = `updated_at` 내림차순(최근 수정 위).
- [ ] 하단 `DialogActions` = "닫기"(outlined).

### 1-4. 편집 뷰 (신규·수정 공용 모드 스왑)
- [ ] 상단 "← 목록으로"(text Button) — 편집 취소 없이 목록 복귀(아래 저장/취소 규칙 참조).
- [ ] **템플릿 이름**(`name`) · TextField · **필수** · placeholder "예) 기본 준비노트" · 빈 이름 저장 차단(인라인 안내 + 저장 버튼 비활성).
- [ ] **본문 편집기** = `PrepNoteEditor`(Toast UI, lazy, Suspense fallback) — **이미지 비활성**(§본문 편집기).
  - `initialValue` = (수정 시)해당 템플릿 `body_html` / (신규 시)빈 문자열.
  - 에디터 하단 안내 1줄(L2와 동일): "Markdown 탭에서 ## 제목 · - [ ] 체크리스트를 바로 입력할 수 있어요".
- [ ] 푸터 액션 = `[취소] [저장]`. 취소 = 편집 폐기 후 목록 뷰. 저장 = CRUD(§데이터 모델) 후 목록 뷰 + "템플릿을 저장했습니다" 토스트.

### 1-5. 본문 편집기 — 이미지 비활성 (1차)
- [ ] `PrepNoteEditor`에 **`disableImage` prop 신규 추가**(frontend-engineer 요청, 전면 재작성 아님 · 소폭 확장):

  2. `addImageBlobHook`이 업로드 대신 **거부 + 안내 토스트** 호출: "템플릿에는 이미지를 넣을 수 없어요. 이미지는 각 학회의 준비 노트에서 직접 삽입하세요."
  3. 붙여넣기/드래그드롭 이미지도 같은 경로로 거부.
  - `bucket`·`idPrefix`는 **불필요**(이미지 없음). 미전달.
- [ ] **근거:** 여러 템플릿/노트가 같은 Storage 이미지를 참조하면 원본 삭제 시 전부 깨진다(`prepNoteImages.js` 서명 URL 수명 관리의 전제와 충돌). 1차는 구조적으로 차단.
- [ ] 저장 본문 = `getHTML()` 결과(HTML). **이미지가 없으므로 `encodeForStorage`(서명 URL→경로 치환)는 불필요** — 서명 URL이 본문에 생길 일이 없다. getHTML 결과를 그대로 `body_html`에 저장.

### 1-6. 삭제
- [ ] 목록 행 "삭제" → **확인 다이얼로그**(`window.confirm` 또는 MUI Dialog, SocietyManagementDialog 톤): "'{이름}' 템플릿을 삭제할까요? 이미 적용한 준비 노트에는 영향이 없습니다."

## 2. 적용 흐름 (L2 반영 요청)

> 대상 = `EventDetailPage.jsx` 준비 노트 섹션(§706~766). `L2_EventDetail.md §7`에 반영 요청.

### 2-1. 빈 노트 — "템플릿으로 시작"
- [ ] L2 준비 노트가 **비어 있을 때**(`!event.prep_note` · 편집 중 아님)의 EmptyState(현재 "준비 노트가 비어 있어요" + "작성하기")에 **보조 액션 "템플릿으로 시작"** 추가(`events:edit`).
- [ ] 클릭 → **템플릿 선택 UI**(템플릿이 여러 개이므로 선택 필요):
  - 간단한 선택 다이얼로그/메뉴 — 템플릿 **이름 목록**(+ 수정일 caption). 각 항목 선택 시 적용.
  - 미리보기는 1차 범위 아님(선택 후 에디터에서 바로 확인·수정). 과한 UI 지양(`룰 E`).
- [ ] 선택 → **기존 편집 진입 경로 재사용**: `setNoteSeed(template.body_html); setEditorKey(k => k+1); setEditingNote(true)`. 즉 템플릿은 `noteSeed`로 주입되는 "씨앗"일 뿐, 이후는 일반 준비노트 편집과 동일.
- [ ] 저장 = **기존 저장 버튼**(`handleSaveNote` → `updateEventPrepNote`). 템플릿 적용 전용 저장 경로는 만들지 않는다.

### 2-2. 노트가 이미 있을 때 — 적용 불허(권장안)
- [ ] 준비 노트에 **내용이 있으면 "템플릿으로 시작"을 노출하지 않는다.** 이미 작성한 노트를 통째로 덮어쓰는 사고(현장 서두름·`01 원칙 3` "되돌릴 수 없는 일은 한 박자 늦게")를 1차에서 구조적으로 차단.
- [ ] **기각한 대안(덮어쓰기 확인):** "기존 노트를 템플릿으로 교체할까요?" 확인 다이얼로그 — 1차 미채택. 이유: 교체 수요가 드물고(뼈대는 빈 노트에서 쓰기 시작), 실수 시 손실이 큼. 정말 교체하려면 운영자가 편집에서 수동으로 비운 뒤 다시 적용. (2차 재검토 여지.)

### 2-3. 템플릿 0개일 때
- [ ] 등록 템플릿이 0개면 "템플릿으로 시작" **미노출** — 빈 상태는 기존 "작성하기"만. (불러올 씨앗이 없는데 버튼만 보이면 혼란.)
- [ ] 기본 템플릿 1건이 있으면 보통 ≥1 유지(§기본 템플릿). 전부 삭제한 경우에만 0개 상태.

### 2-4. 임시저장(`useFormDraft('prepNote', eventId)`)과의 관계
- [ ] 템플릿 주입은 `noteSeed`만 템플릿 본문으로 바꿔 **기존 편집 진입 경로(`handleEditNote` 계열)를 그대로 탄다.** 따라서:
  - 에디터 `onChange` → 기존 `noteDraft.saveDraft(html)` 자동 임시저장이 **그대로 동작**(별도 로직 불필요).
  - 진입 시 유효 draft가 있으면 기존 `DraftBanner`(이어쓰기/새로쓰기) 로직이 그대로 노출된다. 빈 노트 전용이라 보통 draft 없음이지만, 이전에 쓰다 만 draft가 남아 있으면 배너가 뜬다 — 이때 "이어쓰기"는 draft 우선, "새로쓰기"는 현재 저장본(빈)으로 리셋. **템플릿 주입이 draft보다 우선하도록**: "템플릿으로 시작" 선택 시 draft를 무시하고 템플릿을 seed로 재마운트(필요 시 `noteDraft.dismiss()` 호출). 구현 시 1건 명시.
- [ ] 템플릿 전용 임시저장은 만들지 않는다(키 분기 추가 없음 — `prepNote` type 그대로).

### 3-1. seed 저장 형식 (구현 참고)
- [ ] 저장본은 **HTML**(`body_html`) — Toast UI `getHTML()` 결과. 위 마크다운은 사람이 읽는 초안 표현이고, 실제 저장은 에디터가 변환한 HTML이다(`PrepNoteEditor` 동작 — 마크다운 모드로 작성해도 `getHTML()` HTML을 반환, 기존 `prep_note`·Viewer와 동일 정합).
- [ ] **seed 생성 방식(권장):** 손으로 만든 Toast UI HTML은 깨지기 쉬우므로, **배포 후 "준비노트 템플릿" 화면에서 위 초안을 Markdown 탭에 붙여넣어 1회 저장**(getHTML이 정확한 HTML·뷰어 라운드트립 보장). 건우님 검토·수정도 이 과정에서 자연스럽게 이뤄진다.
- [ ] **대안:** 마이그레이션 `INSERT`로 seed 1행(created_by null). 이 경우 body_html은 에디터로 1회 만든 HTML을 그대로 넣어야 함(마크다운 원문 직저장 시 Viewer가 체크박스를 못 그림). → 방식 선택은 CTO/engineer 판단(보고서 §후속 요청).

## 4. 데이터 모델 (CTO 확정 계약 — 이름·타입 변경 금지)

### `prep_note_templates` (신규 테이블)
- `id` bigint identity **PK**
- `name` text **NOT NULL** — 템플릿 이름
- `body_html` text — 본문(Toast UI getHTML HTML). NULL 허용(빈 템플릿)
- `created_by` uuid — 작성자(insert 시 auth.uid, seed는 null)
- `created_at` timestamptz — 생성 시각
- `updated_at` timestamptz — 수정 시각(수정 시 갱신 — app `.update({..., updated_at})` 또는 단순 트리거)
- **RLS = 읽기 authenticated / 쓰기 `events:edit`.** audit 트리거 없음(CTO 계약).

### API 함수 (신규 — `api/events.js`)
- [ ] `getPrepNoteTemplates()` — 목록 `id, name, body_html, updated_at` select, `updated_at` desc. (행 수 적어 `body_html` 포함 로드 → 적용·수정 시 추가 왕복 없음.)
- [ ] `createPrepNoteTemplate({ name, body_html })` — insert. created_by = DB default/auth.uid.
- [ ] `updatePrepNoteTemplate(id, { name, body_html })` — update + updated_at 갱신.
- [ ] `deletePrepNoteTemplate(id)` — delete.

### 회귀 점검 (사고 방지 체크리스트)
> `prep_note_templates`는 신규 테이블이라 `events` 컬럼 누락 사고(2026-06-25) 유형과 무관하다. 다만 **적용 흐름이 기존 prep_note 저장 경로를 재사용**하므로 아래를 확인한다.
- [ ] 템플릿 적용은 `events.prep_note`에 **별도 저장 경로를 만들지 않는다** — `updateEventPrepNote`(기존) 그대로. (적용 전용 update 추가 시 FORM_FIELDS·EVENT_DETAIL_COLUMNS 정합을 깨뜨릴 수 있음.)
- [ ] `PrepNoteEditor` `disableImage` 추가가 **L2·A7 게시판의 기존 이미지 업로드 동작을 깨지 않는지**(prop 미전달 시 기존대로 이미지 활성) 확인 — 기본값 `false`.
- [ ] 템플릿 삭제가 `events.prep_note`에 영향 없음(FK·트리거 없음 — 복사 모델) 확인.

## 7. 핵심 발견 (시안·구현 검수 시 반드시 확인)
1. **템플릿 = 복사 씨앗.** 적용은 `events.prep_note`에 본문을 복사하는 것. 템플릿 수정·삭제는 이미 적용된 노트에 영향 없음(모든 안내 문구가 이 사실을 안심시켜야 함).
2. **1차 이미지 금지.** `PrepNoteEditor disableImage`로 구조적 차단(공유 이미지 삭제 시 깨짐 방지). 전면 재작성 아닌 prop 확장.
3. **빈 노트에서만 적용.** 덮어쓰기는 1차 미채택(현장 사고 방지).
4. **기존 편집·임시저장 경로 100% 재사용.** 템플릿은 `noteSeed` 주입만. 별도 저장/draft 경로 추가 금지.
5. **모달 1개 모드 스왑**(L2 §5-2 idiom). 전용 페이지·2단 모달 기각.
6. **기본 템플릿은 seed 1건이며 수정·삭제 가능.** 고정 fallback 아님. 본문 초안은 §3, 건우님 수정 전제.
7. **진입 버튼 = "학회 목록 관리" 옆, events:edit.** A10 PageHeader 반영 요청.
8. **AI 시그니처 금지(`룰 E`).** 가짜 통계·그라데이션·장식 인디케이터 없음. 목록은 이름·수정일·수정·삭제만.
